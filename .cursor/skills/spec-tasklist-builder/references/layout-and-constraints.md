# 落盘与章节约束

## 主文件一级标题

```markdown
# 需求Spec：xxx功能/页面开发

## 目标描述
## 技术约束
## 功能需求索引
## 任务与进度
## 验收标准
```

## 落盘约定

`area-dir` 下允许**一层** module 子目录（语义：可独立验收的**子组件**，不是「方块文件」）：

```text
.specs/<area>/<slug>.spec.md
.specs/<area>/<slug>/<area-dir>/_index.md
.specs/<area>/<slug>/<area-dir>/<component>.md
.specs/<area>/<slug>/<area-dir>/<module>/<component>.md   # 可选二级嵌套
```

规则：

- 默认可扁平：兄弟组件同放在 `area-dir/`。
- UI 子树较深（如 chat → header → actions）时，在 `area-dir` 下建 **一个** `<module>/` 目录，组件文件放其内；**禁止**再在 module 下继续建更深目录。
- 任务表 `spec` 列写相对主文件的真实路径（可含 `module/` 段）；指向**单个**双层详述文件。
- `_index.md` / 组件 **子组件 (`children`)** 用相对链接指向子文件；用 id + 路径表达父子，不用超长扁平拼接文件名。
- 组件内「方块」写在详述 **分析 → 模块** 章节，**不**单独建方块文件、**不**单独成任务。
- **禁止**把全部组件详述写进主文件；Agent 实现时禁止一次读入全部详述。

## 组件详述章节（方案 C · 同文件双层）

```markdown
# `id` — 名称
（元信息：设计源 / 父节点 / children / 职责）

## 分析
### 目标
### 模块（方块）   # 每块：内容 / 样子 / 可选局部意图
### 整体交互意图   # 意图 → 回调名
### 本期不做 / 待澄清（分析）

## 实现契约
### 状态
### 边界
### 交互            # 事件表
### 输入约束
### 可选参考实现   # 须标「参考（非强制）」
### 本期不做（实现）
### 组件验收
```

- 分析层样子：自然语言，见 `visual-language.md`；禁止默认灌满 Tailwind。
- 实现契约：状态 / 边界 / 事件表+回调 / 验收必填。
- 两层冲突：以分析层视觉意图为准；契约缺项标 `待澄清`。
- 每个 area / 组件必须链到设计源路径。
- 任务 `status`：`todo` | `doing` | `done` | `blocked` | `unknown`。

## `_index.md`

短编排即可：职责、子组件链接、编排交互、复用。**不写**方块级样子。

## 旧格式

冻结的既有详述可能仍是「组成 / UI·Tailwind / 交互」单层。新 `create` 与触达的 `iterate` 必须用双层；未触达文件不强制改写。
