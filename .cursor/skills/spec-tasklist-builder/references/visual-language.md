# 样子公约（自然语言）

何时读：写组件详述「分析 → 模块（方块）→ 样子」时。

## 原则

- 描述**视觉意图**，不描述实现 class。
- 禁止默认写死 px、完整 Tailwind 串、精确色值。
- 颜色用语义：中性 `zinc`、主强调 `red`；并说明明暗是否需区分。
- 仅当设计稿/用户已明确 token 时，可在方块下加一行：`已确认：…`。

## 推荐轴

| 轴 | 写什么 | 示例 |
|----|--------|------|
| 形状 | 圆角程度、圆形/胶囊、分割线有无 | 「大圆角矩形」「圆形裁切」「底部分割线」 |
| 层级 | 主 / 次 / 弱文案或控件 | 「标题主层级略重；摘要次要色」 |
| 密度 | 紧凑 / 舒适；区块间距相对感 | 「间距舒适不紧贴」「操作区与文案松开一档」 |
| 状态 | 默认相对 hover / 选中 / 禁用的变化 | 「选中时背景抬起一档；禁用变弱」 |
| 响应 | 窄屏折叠、换行、隐藏次要、触控变大 | 「窄屏仍通栏，不缩成侧栏小图」 |
| 运动（可选） | 是否需要短过渡 | 「Tab 切换短淡入即可」 |

## 反例

- 坏：`flex min-h-14 items-center gap-3 px-3 py-2`
- 好：整行横排，垂直居中；内边距舒适；选中时中性底抬起

## 与实现契约的关系

- 「样子」只写在**分析**层。
- 实现契约里若给 Tailwind，必须标注 `参考（非强制）`。
- 两层冲突时以分析层为准。
