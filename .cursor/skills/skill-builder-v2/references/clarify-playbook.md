# 澄清 Playbook（按需读取）

在推断「输入 / 输出 / 流程」选项、或某要素表述模糊时打开本文。热路径不必预读。

## 通用提问形态

1. 一行进度。
2. 一句说明「当前确认的是 X」。
3. 若不明确：列出 **A / B / C**（最多 4 个）+「基于某方案优化」+「自定义」。
4. 只等这一项的答复。

## 名字

- 格式：`^[a-z][a-z0-9-]*$`，≤64 字符。
- 可从功能动词+对象建议，如「生成 PR 描述」→ `pr-description-builder`。

## 功能

- 目标句式：`你是…：要完成…`
- 模糊时方案例：
  - A：只做主任务（推荐默认）
  - B：主任务 + 轻度校验/摘要
  - C：主任务 + 多模式（create/iterate 等）

## 触发词

- `description` 须含：做什么 + 何时触发 + 何时不触发。
- 方案例：
  - A：斜杠名 `/skill-name` + 若干中文口令
  - B：纯语义触发（无斜杠），适合高频工作流
  - C：仅显式点名（`disable-model-invocation: true`）

## 输入（按功能推断）

| 方案 | 适用 | 形态 |
|------|------|------|
| A 自由文本 | 短需求、一次说清 | 用户一段话 |
| B 结构化字段 | 多字段、顺序敏感 | 逐项澄清清单 |
| C 文件/路径 | 基于仓库或文档 | 路径 + 可选范围说明 |
| D 混合 | 路径 + 补充约束 | 路径必填，其余可选确认 |

请用户：选方案 / 改字段列表 / 自定义格式说明。

## 输出（按功能推断）

| 方案 | 适用 | 形态 |
|------|------|------|
| A 单文件 | 一份说明/报告 | 指定路径的 md/json 等 |
| B Skill/目录包 | 元工具、多文件 | 目录 + 文件清单 |
| C 对话结论 | 只读分析 | 结构化回复，不落盘 |
| D 表格/清单 | 对比、检查结果 | markdown 表或 checkbox |

## 流程骨架（按功能推断）

每套方案写成 3–6 步；每步三要素：**名称 / 做什么 / 结果**。

**骨架 A — 澄清→执行→交付**

1. 收集输入 → 得到完整输入
2. 执行主任务 → 得到中间产物
3. 格式化交付 → 得到最终输出

**骨架 B — 澄清→计划→批准→执行→自检**

1. 收集输入
2. 展示计划
3. 等用户批准
4. 执行
5. 自检并报告

**骨架 C — 定位→只读分析→可选写入**

1. 定位对象
2. 分析
3. 若用户要求则写入，否则只汇报

用户可：整套选用、合并步骤、或自定义逐步改写。若开启正确性，为每步补一句可观察的「校验」标准（非空、字段齐全、门禁通过等）。

## 边界与正确性（步骤七、八）

- 边界：至少问一次；用户说「无」也记为已确认。
- 正确性选项建议直接给出：
  - A：不强制校验（`none`）
  - B：每步写「校验」（`step_checks`）
  - C：每步校验 + `scripts/skill-self-check.md`（`step_checks+self_check_file`）
