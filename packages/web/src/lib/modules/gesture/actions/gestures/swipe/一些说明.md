# touchmove 滚动阻止与方向锁 —— 业界最佳实践

本文档说明 `swipe.svelte.ts` 中 `onTouchMove`（约 344–365 行）的作用，以及与之相关的业界实践与规范链接。

---

## 这段 `onTouchMove` 在做什么？

这段逻辑解决的是：**同一根触摸上既要支持「横向 swipe」，又不能破坏「纵向滚动」**，并在 **Safari / 移动端** 上补足 Pointer Events 的不足。

### 1. 问题来源：浏览器会抢先接管触摸

- 移动端浏览器会在**前几次 touchmove** 里就决定：这次触摸是「我要用来滚动的」还是「交给页面」。
- 一旦浏览器决定「我要用来滚动」，会：
  - 把这次触摸当成**直接操纵（direct manipulation）**用于 pan/zoom；
  - 对 Pointer 事件**抑制这条指针流**并派发 **`pointercancel`**，后续的 `pointermove` / `pointerup` 可能不再按预期发生。

因此：**若不在 touch 层做任何干预，浏览器可能在你还没判断出「横滑 vs 纵滚」之前就接管触摸并触发 pointercancel，你的 swipe 逻辑就再也拿不到完整序列。**

规范依据（W3C Pointer Events）：

- 在开始 pan/zoom 之前，若 UA 判定这次直接操纵要用于 panning/zooming，则 **MUST suppress the pointer event stream**（并伴随 pointercancel 等）。
- [Pointer Events - pointercancel](https://w3c.github.io/pointerevents/#the-pointercancel-event)
- [Pointer Events - touch-action 与 suppress](https://w3c.github.io/pointerevents/#the-touch-action-css-property) 中 "Right before starting to pan or zoom, the user agent MUST suppress a pointer event stream..."

### 2. 为何不能只靠 Pointer Events + touch-action？

- **touch-action**（如 `pan-y`）可以声明「这里只允许纵向滚动，横向交给我」，浏览器在**手势开始前**会根据它决定是否接管。但：
  - **Safari** 对 touch-action 的支持/行为并不完全一致，尤其在「先不接管、等 JS 判定方向后再放行纵向」这种精细场景下，仍需在 **touch 事件里** 用 `preventDefault()` 才能可靠阻止浏览器抢先滚动。
- MDN 的说明：  
  _"Applications using Touch events disable the browser handling of gestures by calling preventDefault(), but **should also use touch-action** to ensure the browser knows the intent."_  
  [MDN - touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action)

因此：**在需要「先判断方向、再决定是否交给浏览器滚动」的场景，业界常见做法是同时用 touch-action + 在 touchmove 里按条件 preventDefault；你这段就是后者。**

## 一句话总结

**这段 onTouchMove 的作用是：在 Safari/移动端上，用「touchmove + passive: false + 按方向与阈值的条件 preventDefault」在「横向 swipe」和「纵向滚动」之间做分工——在方向未决或横向时阻止浏览器接管触摸（避免 pointercancel 导致 swipe 失效），在明确纵向时立刻放行，避免列表滚动出现前几帧卡顿；和业界「touch-action + 方向锁 + 必要时在 touch 层 preventDefault」的做法一致。**

# setPointerCapture

pointerdown 事件触发前浏览器都会会对 e.target 进行隐式指针捕获；在触发 pointerup, pointercancel 等时间前会先对 e.target 进行隐式指针释放。如果你手动要对 node.setPointerCapture / node.releasePointerCapture 很可能发生意料之外的事情，所以非必要不要手动释放/捕获。
