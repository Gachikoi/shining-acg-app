# 1. 项目综述

## 1.1 背景

1. **官网记忆**：晒你官网已停运许久，社团内部一直有复活官网的呼声，期望通过还原官网数据来重建社团回忆。
2. **产品缺位**：目前市面上缺乏一款能同时满足以下需求的内容生态平台：
   - 帮助晒你人扩展内部社交圈（扩展社交圈）。
   - 将个人创作与社团历史深度绑定（绑定社团）。
   - 提供足够低的创作门槛，消除分享顾虑（低创作门槛）。

   我们希望能制作一款填补上述空缺的产品，让晒你人可以在其中自由创作、随心分享、广泛交流。

## 1.2 产品矩阵

为填补上述空缺，我们打算开发两个紧密关联的产品：

### 1.2.1 晒你官网 (shining-acg-site，简称 site)

- **定位**：社团对外展示风貌的门面与回忆的起点。
- **核心功能**：
  - 展示社团各类基础信息。
  - 聚合展示“晒你 App”的热门帖子。
  - 复刻经典的“部长宣言”模块。

### 1.2.2 晒你 App (shining-acg-app，简称 app)

- **定位**：强绑定 QQ 生态的以`个人创作`、`生活分享`内容为主 UGC 平台。
- **核心功能**：
  - 提供低门槛的内容发布体验。
  - 通过内容渠道帮助用户建立联系，扩展交际圈。
  - 集成对 app 和 site 的管理功能。

## 1.3 竞品分析与差异化

### 1.3.1 对比与优势

前文说过 app 的定位与填补的内容生态平台缺位，因此本节主要针对相同定位（生活分享、个人创作）的 app 进行分析，重点考察现有平台在“扩展社交圈”、“绑定社团”、“低创作门槛”三个方面的表现。

| 平台        | 特点                                               | 优点                                   | 痛点 (针对本社团需求)                                                                                      |
| :---------- | :------------------------------------------------- | :------------------------------------- | :--------------------------------------------------------------------------------------------------------- |
| **QQ 空间** | 强熟人社交链，私密性高，是社团成员目前的存量活跃地 | 创作门槛极低，心理负担小，适合高频分享 | **社交封闭**：无法触达未加好友的社团新人，难以扩展交际圈；<br>**缺乏沉淀**：内容难以检索，无法绑定社团历史 |
| **小红书**  | 强算法推荐，重美感                                 | 标签化分发利于同好聚集，互动氛围好     | **门槛较高**：对质量有要求，劝退了随意的日常记录；<br>**关系疏离**：公域流量为主，难以转化为社团深度社交   |
| **B 站**    | 二次元浓厚，中长视频                               | 适合发布高质量的社团活动记录或个人大作 | **门槛过高**：视频制作耗时，不适合图文形式；<br>**反馈较难**：普通人的日常内容难以获得流量与关注           |
| **抖音**    | 强算法推荐，短视频                                 | 创作工具丰富，爆款曝光大               | **沉淀困难**：消费极度碎片化，难以建立稳定社团社交                                                         |

可以看出，app 锚定了晒你这一独特的群体，在众多社交平台上形成了独特的差异化路线。

### 1.3.2 困境与突围

虽然现有平台存在痛点，但其培养的用户习惯构成了巨大的优势。对于用户来说，‘摆脱痛点’的收益往往难以抵消‘学习新软件’和‘多平台分发’带来的巨大成本。因此，我们不能仅靠痛点驱动，必须在**最小化用户使用门槛**的同时，**最大化我们独有的社团优势**，才能真正吸引用户。

#### 1.3.2.1 最小化使用门槛

1. **无感登录**：利用 QQ 互联实现一键登录，无需记忆额外账号密码。
2. **零成本迁移**：交互逻辑复用主流社交 App (如小红书/QQ 空间) 习惯，降低学习成本。
3. **智能发布**：统一发布入口，系统自动根据素材类型（纯文、单图、多图、视频）适配最佳展示版式。

#### 1.3.2.2 最大化社团优势

1. **身份认同强化**：
   - 在 app 全局强化“部门”概念，用户头像旁常驻部门徽章。
   - site 首页聚合展示 app 优质内容，让普通社员的作品有机会成为社团“门面”。
2. **社交关系沉淀**：
   - **私域互通**：支持个人主页挂载外部社交链接，帮助社员将社团内的弱关系转化为全平台的强关注。
   - **即时触达**：利用原生推送能力，确保社团内的互动（评论、私信）能像 QQ 消息一样被即时感知，解决“回访难”问题。

## 2.2 用户体验及适配方案

支持黑夜模式，适配系统级字体调节；用户在 PC 浏览器、移动端浏览器、移动端 App 均可访问应用。

本项目致力于实现“一次开发，多端运行”，同时支持现代浏览器访问与主流移动平台应用访问。

### 2.2.1 技术架构

采用 "Web Core + Native Shell" 的混合开发模式：

- **核心业务层 (Web)**：基于 Web 技术栈构建统一的业务逻辑与 UI 界面，确保多端体验一致性与迭代效率。
- **原生壳层 (Native)**：
  - **iOS/Android/HarmonyOS**：使用原生 WebView 容器加载 Web 页面。
  - **原生能力桥接**：通过 JSBridge 调用原生通知 (Push Notification)、系统分享等系统级能力。

尽管我们主要采用 Web 技术栈进行开发工作，但是我们寄希望于 Service Worker 技术及对原生客户端能力的调用，为用户提供近似原生应用的体验。

### 2.2.2 UI 适配方案

- **site**：
  - PC 端、移动端分别进行 UI 设计和开发。
  - 若人力不足，优先保证 PC 端开发。
- **app**：
  - 采用全响应式设计，来适配不同尺寸的设备。

后续描述需求时，会使用

1. **PC 端**
2. **移动端**

来声明不同端的设计区别。

虽然 app 采用的是响应式设计没有明显的 **PC 端**和**移动端**分隔，但是也可以按照这两种来区分设计思路。

# 3. 全局规则

## 3.1 时间显示规则

> 含义差别：
>
> “昨天”通常指日历上的“前一日”（the previous calendar day）。
>
> “一天前”（“1 day ago”）更偏向于持续时间，通常理解为大约 24 小时之前（严格含义是距今 >=24 小时且 <48 小时）。

使用“秒”级时间戳。

**原则 A：即时性优先 (用于帖子、评论、互动)**

- < 1 分钟：显示“刚刚”
- 1-59 分钟：显示“xx 分钟前”
- 1-23 小时：显示“xx 小时前”
- 1-6 天：显示“x 天前” (需 >= 24h)
- \>= 7 天 (本年)：显示“MM-DD”
- 非本年：显示“YYYY-MM-DD”

**原则 B：准确性优先 (用于私信、聊天记录)**

- 今天：显示“HH:mm”
- 昨天：显示“昨天 HH:mm”
- 昨天以前，< 7 天：显示“星期 X”
- \>= 7 天 (本年)：显示“MM-DD”
- 非本年：显示“YYYY-MM-DD”

## 3.2 链接跳转规则

白名单（直接跳转）：对于项目内部定义的域名及受信任站点，无论协议，直接跳转。如 \*.shiningacg.club、\*.bilibili.com、\*.xiaohongshu.com、\*.github.com、\*.douyin.com、\*.acfun.cn、\*.skland.com、\*.miyoushe.com、\*.weibo.com。

其他域名（弹窗提醒）：“即将跳转到外部链接，可能存在安全风险，是否仍然跳转？网站链接：xxxxxxx”

## 3.3 数字显示规则

1. 千以内及千级，显示全部数字。如 1、199、9999。
2. 万级，显示为 x.x 万，精确到一位小数。如 1.1 万、9999.0 万。
3. 亿级，显示为 x.x 亿，精确到一位小数。如 1.1 亿、9999.0 亿。

### 4.3.2 准入与鉴权机制

  - 系统自动校验登录 QQ 是否在社团成员白名单中。
  - 非白名单用户只能访问首页、帖子详情，其余模块均无法访问。

## 4.4 用户输入处理系统

1. 输入最大长度：对所有的用户输入都要限制输入的最大长度。如果设计稿标出了字符数限制，则以设计稿为准；如果没有标出，则显示为 1000 个字符。如果超出限制，后端会报错并返回给前端。

2. 安全防范：
   - XSS 注入：前端以安全方式展示用户输入内容，后端不拒绝任何可能存在危险的评论输入，但需要检测所有的“相关链接”中的url是否以http/https开头；后端需要采取措施防范文件上传的 XSS 攻击。
   - SQL 注入：后端使用参数化查询。
   - 跨域限制：只允许 hostname endWith shiningacg.club 的域名访问服务器资源。
   - CSRF：将 token 存在 localstorage 而非 cookie 中。

   详细防止 XSS 注入的措施在——[Web 安全](https://github.com/Gachikoi/shining-acg-app/blob/84b6bc1e70ed1e863e61663d9214fe3d26ea7ebe/docs/%E4%BA%A7%E5%93%81%E9%9C%80%E6%B1%82%E6%96%87%E6%A1%A3.md)中说明。

3. 文件最大尺寸：图片 100 MB，上传服务器前前端预压缩；视频 2 GB。

#### 6.2.3.2 下方帖子瀑布流/用户列表

1. 瀑布流布局：瀑布流撑满页面，根据瀑布流盒子尺寸动态计算每行放置卡片数。

2. 帖子卡片分类：根据帖子内容不同，分为“视频类”和“图文类”。视频类在卡片右上角放置播放 icon。具体的判断逻辑为：当一个帖子在“发布-选择图片/视频”中上传的内容全部为视频时，为“视频类”；如果有图片则为“图片类”。

3. 帖子卡片布局：
   1. 显示封面、标题、帖子发布者头像、帖子发布者用户名、点赞数（带 heart icon）。
   2. 封面比例可为 4:3、1:1、3:4。
   3. 标题最多显示两行；用户名最多显示一行；可以点击“点赞数”进行点赞，如果用户已经对该帖子点过赞则 heart icon 填充红色。
   4. 当**筛选-排序依据**为**推荐**时，在用户昵称下面展示帖子发布时间，采用[`即时性优先`](#31-时间显示规则)的时间显示方案。

4. 瀑布流数据流：
   - 概念：“最新数据”指在最新时刻利用最新数据分析获取到的推荐内容/最高热度内容/最新内容；“历史数据“指在用户上一次获取“最新数据”的那个时刻获取到的推荐内容/最高热度内容/最新内容，和最新数据内容可能会有差别。
   1. 从顶部下拉获取"最新数据"、加载成功后清除所有当前内容分类的旧内容与缓存，缓存并展示最新内容。
   2. 从底部上滑再在瀑布流下方追加"历史数据"，当数据没返回瀑布流底部显示 loading，数据返回后如果没有新的数据显示“已经到底了”，如果有新的数据则展示新的帖子卡片并根据数据中每个帖子图片的宽高信息来确定帖子中图片的宽高，以防止布局变动。
   3. 初次进入页面时，如果没有缓存的数据，则显示骨架屏并自动发起新数据请求获取最新数据；如果有缓存的数据，则显示缓存的数据并自动发起新数据请求获取最新数据。
   4. 切换内容分类时，如果没有缓存的数据，则显示骨架屏并自动发起新数据请求获取最新数据；如果有缓存的数据，则显示缓存的数据，但不请求最新数据。
   5. 因为这是一个“无限滚动”瀑布流，会无限获取“历史数据”，所以需要为每个用户保存一份“历史数据”的快照，当快照内的数据用光后，再去请求“最新数据”辅以去重，来伪装成“历史数据”。这里要求为前 500 条“历史数据”进行精确去重，以防止用户看到重复的帖子。
   6. 筛选条件：排序依据为“推荐”时，用推荐引擎获取内容；为”最新“时，根据帖子发布时间戳获取内容；为”最热“时，用推荐引擎/根据帖子浏览、点赞、评论、收藏数据获取内容；可结合”日期范围选择器“进行时间限定。

5. 瀑布流持久化缓存：缓存用户上一次访问该页面时的内容，以在下次进入应用时展示给用户替代骨架屏。没有缓存时显示骨架屏并自动发起新数据请求。要求在app完全关闭的情况下，缓存依旧能长期存在。

6. 帖子骨架屏：当用户没有瀑布流缓存与已加载的帖子数据时，展示骨架屏并主动发起新数据请求。

7. 交互：点击帖子卡片进入目标**帖子详情页**，**以 Stack 布局呈现**。

#### 6.2.8.2 分享功能

1. 点击按钮后，以`【标题】链接`的形式将帖子标题和帖子链接复制到用户剪切板中，并弹出 toast 提示“已复制分享链接至剪切板，快去分享给好友吧！”
2. 当用户点击他人的分享链接后，在 PC 端会自动从浏览器中打开对应的帖子；如果在手机端，需要跳转到晒你App手机应用中并打开对应帖子。

### 6.2.12 图片视频预览编辑器

1. 文件大小限制：图片最大 100 MB，视频最大 2 GB。

2. 兼容性：支持 JPG、JPEG、PNG、HEIC、HEIF、WebP 图片格式，MP4、MOV、M4V、WebM 视频格式，以及 live photo。由于 MKV 视频格式的复杂性，暂不支持 MKV。

3. 上传流程：
   1. 从系统相册中选择，支持多选。
   2. 选中后在网站中向展示图片/视频的缩略图。
   3. 等到用户实际发布内容时，再将图片上传到服务器。图片需要在上传服务器前预压缩。

4. 编辑：长按+托拽编辑顺序；长按或者鼠标右键弹出 popover 显示“编辑”/“删除”选项；点击“删除”将该图片/视频去掉；点击“编辑”将全屏打开图片视频编辑器，可裁切图片比例，可按照要求比例强制比例裁切，暂时不支持以视频作为编辑对象。

5. 预览：
   1. 图片：
   - 单击图片缩略图/帖子详情中的图片后，全屏打开图片预览器。
   - 全屏打开时背景颜色为黑色，在帖子详情内快速浏览时背景颜色为 zinc/100。
   - 支持左右滑动切换图片/视频（如果没有可切换的图片/视频则变为退出预览），支持上下滑动退出预览，支持单击退出预览，支持双击将图片填充满屏幕。
   2. 视频：
   - 单击视频缩略图/帖子详情中的视频右下角的全屏按钮后，全屏打开视频预览器。
   - 全屏打开时背景颜色为黑色，在帖子详情内快速浏览时背景颜色为 zinc/100。
   - 全屏打开时，根据视频比例，自动切换竖屏横屏。
   - 视频播放时，长按视频左右边缘 2.0 倍速播放视频，双击暂停播放；如果此时全屏，则左右滑动调整视频进度；如果此时非全屏，则左右滑动切换图片/视频。
   - 视频暂停时，长按视频左右边缘 2.0 倍速播放视频，左右滑动切换图片/视频，上下滑动退出预览，单击“播放按钮”或双击页面其他位置恢复播放；
   - **视频控制界面**自动隐藏但可以单击调出。

6. 下载：
   1. 图片：长按/右键弹出popover，可以选择下载当前图片或下载全部图片/视频。
   2. 视频：右键/长按视频中间部分（因为长按左右边缘是 2.0 倍速播放的功能）弹出 popover，可以选择下载当前视频或下载全部图片/视频。

7. 视频控制界面：播放进度条、播放/暂停按钮、倍速设置、音量设置、切换全屏按钮。**移动端**隐藏音量设置按钮（注意！这里的移动端指的是通过 UA 检测出为移动端设备，不能通过媒体查询判断移动端）。
