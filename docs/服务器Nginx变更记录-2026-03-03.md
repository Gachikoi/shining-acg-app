## 为什么不是 localhost:9000

结合以下配置文件分析：
- `packages/server/docker-compose.yml`
- `.github/workflows/ci.yml`
- `.github/workflows/release.yml`

结论：
1. `packages/server/docker-compose.yml` 中，应用对 MinIO 的服务发现写法是容器服务名（`minio-dev:9000`），不是 `localhost`。
2. 线上网关 `main-gateway` 运行在容器里。对 Nginx 容器而言，`localhost` 指向网关容器自身，不是 MinIO 容器。
3. 线上实际拓扑里，`main-gateway` 与 `minio-dev` 在同一个 Docker 网络（`shining_network`），应通过服务名互通。
4. `ci.yml` 的部署只更新 `api-dev` / `api-prod`，不会替你把 Nginx 上游自动改成 `localhost`。
5. `release.yml` 只做前端/安卓发布，不参与服务器 Nginx/MinIO 路由。

因此在当前架构中，Nginx 上游应使用容器服务名（`minio-dev` / `minio-prod`），而不是 `localhost`。
