## 官网编辑表单结构说明

本文档梳理当前「官网编辑」页面的整体表单结构，并给出「部门信息」模块（第三大点）的详细开发计划，作为前后端和设计协作的统一依据。

---

## 一、表单整体结构概览

当前「官网编辑」页面整体上由以下几个一级模块自上而下组成（后续如新增模块可继续在此补充）：

1. **首页视频**
2. **了解我们**
   - 2.1 关于晒你
   - 2.2 相关链接
   - 2.3 联系晒你
3. **部门信息**
   - 3.1 Logo
   - 3.2 宣传图
   - 3.3 宣传视频 / 链接
   - 3.4 中文名
   - 3.5 英文名
   - 3.6 简介
   - 3.7 相关链接
4. **活动信息**
   - 4.1 宣传图
   - 4.2 宣传视频 / 链接
   - 4.3 中文名
   - 4.4 英文名
   - 4.5 简介
   - 4.6 相关链接
5. **部长宣言**
   - 5.1 顶部届数 Tab（如 2023-2024（19 代目）等）
   - 5.2 上任时间
   - 5.3 各部长信息
     - QQ 号
     - 统领部门
     - 简介
6. **关于网站**
   - 6.1 赞助感谢
     - QQ 号
     - 赞助金额
     - 简介
   - 6.2 网站 Staff
     - QQ 号
     - 职责
     - 简介

下面分别说明当前实现状态与字段含义。

---

## 二、首页视频（第一大点，已实现）

**模块位置**：页面最上方，单独一级模块。

**字段与交互**

- **首页视频**
  - 使用组件：`VideoUpload`
  - 内容：
    - 视频上传（本地文件，16:9）
    - 视频链接（可输入外部地址）
  - 交互：
    - 上传视频后在卡片中显示预览缩略图
    - 填写/修改视频链接时，同步更新本地状态

**前端状态字段**

- `homepageVideo: string`  
  用于存储视频文件上传后的 URL（目前为 `URL.createObjectURL`，后续可替换为真实上传地址）。

- `homepageVideoLink: string`  
  外部视频链接。

## 三、了解我们（第二大点，已实现）

**模块位置**：紧跟在「首页视频」之后，标题为「了解我们」。

### 3.1 关于晒你（必填）

- **组件**：`Textarea` + `CharCounter`
- **UI 要求**：
  - 灰色背景大块文本区域
  - 右下角显示字数计数 `当前字数/300`
  - 标签文案：`关于晒你*`
- **交互**：
  - 输入时实时更新字数并限制最大 300 字

**字段**

- `aboutShining: string`（最多 300 字）

### 3.2 相关链接

- **结构**：列表 +「新增」按钮
- **单条链接字段**（复用 `LinkItem` 组件）：
  - 文字说明（必填）
    - `label: string`，最大长度 12
  - 链接（必填）
    - `value: string`，最大长度 200
- **交互**：
  - 可点击「新增」添加一条空链接
  - 每条右侧有减号按钮，可删除当前条目
  - 样式与产品设计稿保持一致（胶囊输入框 + 右侧计数/图标）

**字段**

- `relatedLinks: Link[]`
  - `Link = { label: string; value: string }`

### 3.3 联系晒你（必填）

- **组件**：`Textarea` + `CharCounter`
- **UI 要求**：同「关于晒你」，但标签和占位符不同
  - 标签文案：`联系晒你*`
  - 占位符：`填写联系方式`
  - 文本区域高度与「关于晒你」一致
  - 右下角字数计数 `当前字数/300`

**字段**

- `contactShining: string`（最多 300 字）

## 四、部门信息（第三大点，结构说明）

「部门信息」模块由**顶部部门 Tab** 与**下方单个部门的详细表单**组成，目前已在页面中实现，布局与设计稿保持一致。

### 4.1 结构说明

1. **部门 Tab 区**
   - 顶部一排 Tab：例如「横斑部 / 宣宣部 / 轻文部 / COS 部 / 宅舞部 / … / 未命名*」
   - 右侧有「+」按钮用于新增部门
   - 点击不同 Tab，在下方展示对应部门的表单内容

2. **单个部门表单字段（当前范围）**
   1. **Logo**（1:1）
   2. **宣传图**（16:9）
   3. **宣传视频 / 链接**
      - 上传视频
      - 视频链接输入框
   4. **中文名**
   5. **英文名**
   6. **简介**
   7. **相关链接**

3. **数据结构（基于现有类型）**

使用已有 `DepartmentInfo` 类型：

- `departments: DepartmentInfo[]`
- `DepartmentInfo`：
  - `id: string`               // 部门 ID
  - `logo: string`             // Logo URL（1:1）
  - `promotionalImage: string` // 宣传图 URL（16:9）
  - `promotionalVideo?: string`// 宣传视频 URL（可选）
  - `videoLink?: string`       // 视频链接（可选）
  - `chineseName: string`      // 中文名（≤20）
  - `englishName?: string`     // 英文名（≤20）
  - `description: string`      // 简介（≤200）
  - `relatedLinks: Link[]`     // 相关链接列表（结构与上文相同）

## 五、「活动信息」模块结构与开发计划（第四大点）

### 5.1 结构说明

「活动信息」模块与「部门信息」整体布局一致，同样由**顶部活动 Tab** 与**下方单个活动的详细表单**组成。

1. **活动 Tab 区**
   - 顶部一排 Tab：例如「晒你祭 / 晒你再年祭 / 绘画大赛 / 模拟 8 小时 / COS 团片 / …」。
   - 右侧有「+」按钮用于新增活动。
   - 点击不同 Tab，在下方展示对应活动的表单内容。

2. **单个活动表单字段**

参考 `ActivityInfo` 类型：

- **宣传图\***（16:9）
- **宣传视频 / 链接**
  - 上传视频
  - 视频链接输入框
- **中文名\***
- **英文名**
- **简介\***
- **相关链接**

`ActivityInfo` 结构如下：

- `activities: ActivityInfo[]`
- `ActivityInfo`：
  - `id: string`               // 活动 ID
  - `promotionalImage: string` // 宣传图 URL（16:9）
  - `promotionalVideo?: string`// 宣传视频 URL（可选）
  - `videoLink?: string`       // 视频链接（可选）
  - `chineseName: string`      // 中文名（≤200）
  - `englishName?: string`     // 英文名（≤20）
  - `description: string`      // 简介（≤200）
  - `relatedLinks: Link[]`     // 相关链接列表

### 5.2 状态与基础结构

1. **前端状态**
   - 在 `+page.svelte` 中维护：
     - `activities = $state<ActivityInfo[]>([默认活动对象])`
     - `activeActivityIndex = $state(0)`
   - 默认至少一个活动（可命名为「未命名活动」或其它默认名）。

2. **基础容器**
   - 在「部门信息」之后增加「活动信息」模块标题。
   - 下方包含：
     - 活动 Tab 区（用于切换活动）
     - 当前活动表单区域（用于编辑单个 `ActivityInfo`）

### 5.3 活动 Tab 区实现

1. **Tab 渲染**
   - 根据 `activities` 渲染一排 Tab，展示活动中文名（无中文名时显示「未命名」）。
   - 当前激活 Tab 由 `activeActivityIndex` 控制，高亮样式与部门 Tab 保持一致。

2. **新增活动按钮**
   - 右上角 `+` 按钮：
     - 点击时向 `activities` 追加一个默认对象（空宣传图/文案等）。
     - 自动切换 `activeActivityIndex` 到新活动。

3. **Tab 切换逻辑**
   - 点击 Tab 时更新 `activeActivityIndex`，下方表单展示对应 `activities[activeActivityIndex]`。
   - 初期版本不做「未保存提示」，后续如有需要再增加「离开确认」逻辑。

### 5.4 单个活动表单字段实现

1. **宣传图**
   - 复用 `ImageUpload` 组件：
     - `aspectRatio="16:9"`，文案提示 「比例最好在 16:9 左右」。
   - 点击上传后，将返回 URL 填入 `activity.promotionalImage`。

2. **宣传视频 / 链接**
   - 复用 `VideoUpload` 组件：
     - 支持上传本地视频（生成预览）。
     - 「视频链接」输入框填写 `videoLink`。
   - 绑定字段：`activity.promotionalVideo` / `activity.videoLink`。

3. **中文名 / 英文名**
   - 使用 `Input` 组件：
     - 中文名：必填，长度 ≤ 200（与类型一致）。
     - 英文名：选填，长度 ≤ 20。

4. **简介**
   - 使用 `Textarea` + `CharCounter`：
     - 最大 200 字（右下角 `x/200`）。
     - 样式与活动设计稿中的简介区域一致（大块浅灰、圆角等）。

5. **活动相关链接**
   - 复用 `LinkItem` 组件：
     - 字段：`activity.relatedLinks: Link[]`。
     - 每条包含文字说明（≤12）与链接（≤200）。
   - 提供「新增」按钮与每条右侧「删除」按钮，样式对齐「了解我们 > 相关链接」。

### 5.5 校验与交互细化

1. **必填项校验（初版建议）**
   - 每个活动至少应填写：
     - 宣传图
     - 中文名
     - 简介
   - 其它字段（视频、英文名、相关链接）是否强制必填，可按后续产品要求再收紧。

2. **保存 / 发布前检查**
   - 在 `handleSave()` / `handlePublish()` 中，对 `activities` 做一轮前端校验：
     - 若存在未填必填字段，阻止保存并在控制台标明问题字段。
     - 如需更完善体验，可在后续版本增加字段级错误提示文案。

3. **状态输出**
   - 更新 `handleSave()` 打印/提交的数据结构，包含：
     - `homepageVideo`, `homepageVideoLink`
     - `aboutShining`, `contactShining`
     - `relatedLinks`
     - `developmentHistory`
     - `departments`
     - `activities`

## 六、「部长宣言」模块结构与开发计划

### 6.1 模块定位与入口

- **位置**：位于「活动信息」之后，为官网编辑中的独立模块，标题为「部长宣言」。
- **功能目标**：按「届数 / 学年」管理各届部长的上任时间与个人宣言信息，并在官网展示。

### 6.2 顶部届数 Tab 结构

- **UI 结构**
  - 顶部一排 Tab，如：`2023-2024（19 代目） / 2022-2023（18 代目） / 2021-2022（17 代目） / 2020-2021（16 代目） / 未命名* / ……`
  - 右侧有「+」按钮：用于新增一届。
  - 当前激活 Tab 高亮，切换时下方表单内容随之切换。

- **交互**
  - 点击某个届数 Tab：
    - 更新 `activeTermIndex`；
    - 下方展示对应届数的「上任时间」和「各部长信息」表单。
  - 点击右侧「+」：
    - 向 `terms` 数组追加一个默认对象（默认名称如「未命名届次」）；
    - 自动切换 `activeTermIndex` 到新建届数。

- **建议数据结构**

```ts
interface MinisterTerm {
	id: string;              // 唯一 ID
	label: string;           // Tab 显示文案，如「2023-2024（19 代目）」；可编辑
	startDate: string;       // 上任时间（YYYY-MM-DD）
	ministers: Minister[];   // 各部长信息
}

interface Minister {
	id: string;
	qq: string;              // QQ 号（≤20）
	departmentId: string;    // 统领部门，对应部门 ID 或枚举
	introduction: string;    // 简介（≤200）
}

let terms = $state<MinisterTerm[]>([/* 默认一届 */]);
let activeTermIndex = $state(0);
```

### 6.3 单个届数表单字段

#### 6.3.1 上任时间（必填）

- **字段**
  - `startDate: string`，日期格式 `YYYY-MM-DD`。
- **组件与 UI**
  - 使用日期选择器组件（如 `DatePicker` / `Input[type="date"]`）；
  - 标签：`上任时间*`；
  - 占位符：`June 01, 2025`（示例）。
- **校验**
  - 必填；
  - 仅允许选择合理范围（例如不能早于社团成立日期 / 不能晚于当前日期，具体规则可后续细化）。

#### 6.3.2 各部长信息（列表）

- **整体结构**
  - 标题文案：`各部长信息*`；
  - 标题下方可有说明文案：如「依据 QQ 号关联晒你 App 用户信息，用于官网展示」；
  - 下方为可增删的部长列表，每条一行表单。

- **单条部长信息字段**
  1. **QQ 号\***  
     - 组件：`Input`  
     - 字段：`minister.qq: string`  
     - 限制：最大长度 20；仅数字校验可在后续版本加上。
  2. **统领部门\***  
     - 组件：`Select`（下拉选择）  
     - 字段：`minister.departmentId: string`  
     - 选项来源：从已有部门列表（例如部门信息模块的 `departments`）中生成。  
     - 占位文案：`选择统领部门`，选中后显示部门中文名（如 `Cosplay`）。
  3. **简介\***  
     - 组件：`Textarea` + 右下角字数计数  
     - 字段：`minister.introduction: string`  
     - 限制：最大 200 字，右下角显示 `当前字数/200`；  
     - 占位符：`填写简介`。

- **列表增删与交互**
  - 列表下方有「+ 新增」按钮：
    - 点击时向当前届数的 `ministers` 数组追加一条空记录（仅 id，其他为空）。
  - 每条右侧有减号按钮：
    - 点击后删除该条部长信息；至少保留一条或允许全部删除，按产品最终决定。
  - 输入任意字段时：
    - 立即更新 `terms[activeTermIndex].ministers` 中对应对象；
    - 文本框和字数计数实时同步。

### 6.4 校验与保存逻辑（建议）

- **必填校验**
  - 每一届需满足：
    - `startDate` 已填写；
    - 至少一条 `minister`；
    - 每条 `minister` 的 `qq`、`departmentId`、`introduction` 均不为空；
    - `qq` 长度 ≤ 20，`introduction` 长度 ≤ 200。
- **保存 / 发布时**
  - 在 `handleSave()` / `handlePublish()` 里，将 `terms` 一并提交；
  - 若存在未填项：
    - 阻止提交；
    - 控制台输出问题字段（后续可接入前端错误提示组件）。

### 6.5 与其它模块的关系

- `departmentId` 使用与「部门信息」模块一致的数据源，确保部门名称与 ID 对齐；
- 官网展示时，可根据 `terms` 中的 `startDate` 与 `label` 决定排序规则（例如按时间倒序展示最近一届在最前）。

## 七、「关于网站」模块结构与开发计划（第六大点）

interface SponsorItem {

#### 7.3.4 数据结构

```ts
interface StaffItem {

	qqNumber: string;          // QQ 号（≤20）

	description?: string;     // 简介（≤200）
}

let staff = $state<StaffItem[]>([]);
```

### 7.4 前端状态与基础结构

1. **前端状态**
   - 在 `+page.svelte` 中维护：
     - `sponsors = $state<SponsorItem[]>([])`
     - `staff = $state<StaffItem[]>([])`
   - 初始状态为空数组，用户可自行添加。

2. **基础容器**
   - 在「部长宣言」之后增加「关于网站」模块标题。
   - 下方包含两个并列的子模块：
     - 「赞助感谢」区域
     - 「网站 Staff」区域

### 7.5 UI 布局要求

1. **字段布局**
   - 每个字段组采用横向布局：左侧标签（固定宽度 `w-20`），右侧输入框（`flex-1`）。
   - QQ 号和第二个字段（赞助金额/职责）使用单行输入框，右侧显示字符计数。
   - 简介使用多行文本区域，右下角显示字符计数。

2. **列表项布局**
   - 每条记录采用横向布局：左侧为字段区域（`flex-1`），右侧为删除按钮（圆形，垂直居中）。
   - 无背景色、无内边距、无边框的简洁样式。

3. **删除按钮样式**
   - 圆形按钮：`size-8`、`bg-zinc-200`、`dark:bg-zinc-800`
   - 使用 `Minus` 图标，白色图标
   - 垂直居中对齐

### 7.6 校验与保存逻辑（建议）

- **必填校验**
  - 每条赞助感谢项需满足：
    - `qqNumber` 已填写且长度 ≤ 20
    - `sponsorAmount` 已填写且长度 ≤ 20
    - `description` 已填写且长度 ≤ 200
  - 每条网站 Staff 项需满足：
    - `qqNumber` 已填写且长度 ≤ 20
    - `role` 已填写且长度 ≤ 20
    - `description` 已填写且长度 ≤ 200

- **保存 / 发布时**
  - 在 `handleSave()` / `handlePublish()` 里，将 `sponsors` 和 `staff` 一并提交；
  - 若存在未填项：
    - 阻止提交；
    - 控制台输出问题字段（后续可接入前端错误提示组件）。

### 7.7 与其它模块的关系

- 两个子模块的说明文案与「部长宣言 > 各部长信息」保持一致，强调依据 QQ 号关联晒你 App 用户信息。
- 字段布局与交互方式参考「部长宣言 > 各部长信息」的实现，保持 UI 一致性。
